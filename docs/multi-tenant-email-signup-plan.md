# 邮箱验证码注册、多账号与每用户 API Key：现状核查与方案

> 本文是「外部邮箱注册 + 邮箱验证码 + 多账号 + 每用户独立 API Key + 高并发」的第一阶段交付：
> 先核查现有部署与邮件通道，再给出多租户隔离粒度的方案和分阶段实施计划。确认后按第 6 节实施代码。

## 1. 结论摘要

- **邮件通道目前不存在**：现有部署没有配置任何 SMTP / 邮件 API 凭据，主机也没装 sendmail/msmtp；
  但主机出站 SMTP 端口实测可达（465/587），所以拿到账号凭据后即可接入。真实送达验证需要你提供发件账号。
- **多租户建议采用「账号级隔离（L1）」**：每个注册用户拥有独立的设置与模型 API Key、任务与成片、
  素材库、角色/道具库、发布记录与抖音授权；平台级配置（邮件通道、注册开关、抖音应用凭证、公网地址）
  只由管理员维护。管理员保留账号治理（禁用/删除/重置密码）与总览，不再负责创建成员。
- **高并发的关键在于存储与任务调度，不在 HTTP 层**：当前账号/设置/发布记录都是「整份 JSON 覆盖写」，
  任务队列单进程串行，会话只在内存（每次自动部署重启都会把所有人踢下线）。方案建议：
  账号/验证码/会话改为 SQLite(WAL) 或按用户分文件，会话改无状态签名 Cookie，验证码发送走异步队列 + 限流，
  视频任务改为有界并发 + 每用户公平队列。单机 12 核 / 15 GB 足够支撑外部注册的请求量。
- **公开注册前必须先有 HTTPS**：控制台目前只通过 `http://<公网IP>:8088` 暴露，HTTPS 入口只转发
  `/api/public/` 素材路径。用 HTTP 收密码和验证码不可接受，建议先落域名 + 证书，或暂时保持「注册关闭」。

## 2. 现有部署核查（2026-11-27 实测）

| 项目 | 现状 |
| --- | --- |
| 运行方式 | `systemctl --user video-agent`，单进程 Node 22.23.2，`127.0.0.1:8787`，`Restart=always` |
| 对外入口 | nginx `0.0.0.0:8088` 反代（纯 HTTP，无 TLS）；另有 Cloudflare Quick Tunnel 只暴露 `/api/public/` 素材中继（HTTPS，URL 会变） |
| 自动部署 | cron 拉 `main` → 构建 → `systemctl restart` → 健康检查；**重启会清空内存会话** |
| 主机 | 12 核 / 15 GB 内存，出站网络正常 |
| 账号 | `data/users.json`（0600，scrypt 加盐），管理员在设置中创建成员；无邮箱字段、无邮箱验证 |
| 会话 | 进程内 `Map`，7 天 TTL，HttpOnly + SameSite=Lax（无 Secure）；重启全失效 |
| 登录限流 | 进程内信号：10 分钟 8 次失败封 5 分钟 |
| 设置 | 全局 `data/settings.json`：脚本/配音/画面/角色图/对口型/抖音的密钥都在这一份里，保存后新任务生效 |
| 资源 | `output/<jobId>/`、`materials/`、`cast/`、`publishes.json`、抖音 token、H5 分享记录**全部全局共享**，任务与发布记录没有 owner 字段 |
| 任务 | 单进程单队列**串行**执行；任务创建时快照当前全局配置 |
| 持久化 | users/settings/publishes 都是整文件 JSON 重写；无数据库 |
| 公开素材 | `/api/public/cast/*`、`/api/public/video/*` 用全局签名密钥/令牌访问，不区分用户 |

结论：当前是「单管理员 + 单工作区」模型，改成外部注册的多账号平台，需要同时改账号、认证、设置、资源与
任务调度，属于一次跨模块的架构调整，不是局部改动——因此先出方案再动手。

## 3. 邮件通道核查

### 3.1 实测结果

| 检查项 | 结果 |
| --- | --- |
| `smtp.qq.com:465` / `:587` | TCP 可达 |
| `smtp.163.com:465` | TCP 可达 |
| `smtpdm.aliyun.com:465` | TCP 可达 |
| `smtp.gmail.com:587` | TCP 可达 |
| 本机 MTA（sendmail/msmtp/mailx） | 未安装，无法本地投递 |
| 部署目录 `.env` | 不存在 |
| systemd 单元环境变量 | 只有 PATH / NODE_ENV，无 SMTP 变量 |
| `data/settings.json` | 无 mail 配置；只有模型类密钥 |
| 主机其它项目 | 无已配置的邮件凭据（只有 dify 的示例模板，未启用） |

### 3.2 结论与建议

- 出站网络没问题，**缺的是发件账号/域名和凭据**；没有它们就无法在本机验证「真实收到验证码」。
- 通道形式建议做成可切换的两种驱动，启动时按配置选择：
  1. **SMTP**（`host/port/secure/user/pass/from/fromName`）——最通用，个人邮箱授权码即可先跑通；
  2. **HTTP 邮件 API**（服务商地址 + API Key + 发件人）——适合量大、需要回执/退信处理的场景。
- 生产建议用**带自有域名**的邮件服务（阿里云邮件推送 DirectMail、Resend 等），域名需配 SPF/DKIM/DMARC；
  个人邮箱 SMTP（QQ/163）有每日额度限制、容易进垃圾箱、也可能因发送量被风控，只适合验证阶段。
- 验证方式：
  1. 本地集成测试用假 SMTP 服务（sink）跑通「注册→发码→校验→登录」；
  2. 你填好凭据后在部署上点一次「发送测试邮件」，确认能收到；
  3. 再用真实邮箱走一遍完整注册闭环。
- 部署侧不需要改 nginx/网络；发信端口用 465/587，避免 25（可能被运营商封）。

## 4. 多租户隔离粒度（方案对比）

| 维度 | L0 仅个人 Key | **L1 账号级隔离（推荐）** | L2 团队/组织 |
| --- | --- | --- | --- |
| 设置与模型 API Key | 每人一份 | 每人一份 | 每组织一份，成员共享 |
| 任务与成片 | 全局可见 | 仅本人（管理员可治理性查看） | 组织内可见 |
| 素材库 | 全局共享 | 每人独立 | 组织内共享 |
| 角色/道具 | 全局共享 | 每人独立 | 组织内共享 |
| 发布记录/抖音授权 | 全局共享 | 每人独立 | 组织内共享 |
| 管理员职责 | 全局配置 + 建号 | 账号治理 + 平台配置 | 组织与成员管理 |
| 与现架构距离 | 最小 | 中（按 userId 分区 + 迁移） | 大（新增组织模型） |
| 风险 | 用户互相看到成片/素材，不符合「多账号平台」 | 改动可控，符合独立账号预期 | 当前阶段过度设计 |

**推荐 L1**，理由：

- 每个账号配置自己的模型 Key，成本和额度天然按人隔离；
- 用户上传的素材、角色图和成片属于个人内容，跨账号可见会造成隐私与版权问题；
- 与现有数据模型差异最小：把现在的「全局单例」按 `userId` 分区即可，保留管理员治理入口；
- L2 的团队/组织共享可以以后再叠加，不影响 L1 的数据结构。

**建议的边界**：

- **按用户隔离**：模型/配音/画面/角色图/抖音等 API Key 与个人偏好；任务、进度、成片、字幕、脚本；
  素材库；角色/道具与参考图；发布记录、抖音 OAuth 授权、H5 分享；个人用量统计。
- **平台共享（仅管理员可改）**：邮件通道与注册开关、抖音开放平台应用凭证（clientKey/secret）、
  公网素材地址与签名密钥、服务器/端口、日志与备份路径。
- **可选**：管理员维护的公共模板库（角色/素材模板），用户可克隆到自己的空间，不反向共享。

**迁移**：现有唯一管理员的数据整体归入该账号命名空间（`output/users/<adminId>/` 等），旧数据可读；
迁移脚本幂等并留备份，不改动 `data/` 以外的目录。

## 5. 目标设计（L1）

### 5.1 账号与邮箱验证

- `UserRecord` 增加：`email`（唯一、小写归一）、`emailVerifiedAt`、`status: active|disabled`、
  `sessionVersion`（改密/禁用时递增，用于让旧会话失效）；保留 `username` 作为历史管理员登录兼容字段。
- 注册流程：
  1. `POST /api/auth/signup {email, password, displayName?}` → 创建未验证账号（或待验证记录），异步发 6 位数字码；
  2. `POST /api/auth/verify-email {email, code}` → 校验通过后标记已验证并建立会话；
  3. `POST /api/auth/resend-code {email}` → 冷却与限流后重发；
  4. `POST /api/auth/login {email, password}` → 未验证账号提示先验证，禁用账号统一报错；
  5. `POST /api/auth/forgot-password {email}` + `POST /api/auth/reset-password {email, code, password}`。
- 验证码规则：6 位数字（`crypto.randomInt`）、10 分钟有效、一次性、只存 HMAC 哈希；
  单码最多 5 次尝试；同邮箱 60 秒内不可重发、每小时 10 次、每天 30 次；同 IP 每小时 30 次。
- 防枚举：注册/重发/忘记密码对「已注册/未注册」返回同一文案与相近耗时；注册不直接登录。
- 管理员：保留首次 `setup` 创建管理员（部署是单管理员起步）；之后成员只能邮件注册；
  管理员可禁用/启用/删除/重置密码，不再提供「创建成员」入口（保留 API 兼容一个版本，UI 移除）。
- 注册开关：`registration.enabled` 默认关闭，配置在平台级设置；可追加 `allowedEmailDomains`、
  邀请码（默认不做，留字段）。

### 5.2 每用户 API Key 与设置

- 新增 `UserSettingsStore`：每人 `data/users/<userId>/settings.json`（0600），沿用现有
  `serializeSettings` / `sanitizeSection` 的合并与脱敏逻辑，基座仍是 `DEFAULT_CONFIG` + 环境变量。
- 拆分：
  - 个人设置：`script`、`tts`、`videoGen`、`imageGen`、`lipsync`、个人视频/字幕偏好；
  - 平台设置：`server`、`mail`、`registration`、`douyin.clientKey/clientSecret`、`publicBaseUrl`、
    `publicAssetToken`、路径配置。只有管理员能改，普通用户只读必要展示项。
- 任务创建时用**创建者的合并配置**做快照（沿用 `buildJobConfig`），任务运行期间改设置不影响在跑任务。
- 设置页「测试配置」按钮（脚本/配音/画面/抖音）改为用当前登录用户的 Key 执行；新增「平台邮件通道测试」仅管理员可见。
- 响应继续脱敏（`apiKeySet` + 末 4 位提示），绝不回显完整 Key 或验证码。

### 5.3 数据隔离

| 资源 | 新位置 / 规则 |
| --- | --- |
| 个人设置 | `data/users/<userId>/settings.json` |
| 任务与成片 | `output/users/<userId>/<jobId>/`；`JobRecord.userId`；列表/详情/文件下载校验归属，管理员可治理性查看 |
| 素材库 | `materials/users/<userId>/` |
| 角色/道具 | `cast/users/<userId>/` |
| 发布记录 | `publishes.json` v2（每条带 `userId`），或每人一个文件 |
| 抖音授权 | `data/users/<userId>/douyin-token.json` |
| H5 分享 | 记录带 `userId`，查询按用户过滤 |
| 公开素材签名 | 签名令牌绑定 `userId + 路径 + 过期时间`，防止跨用户盗链 |

迁移：启动时一次性把旧目录内容移入管理员命名空间（幂等标记），并保留 `.bak-<时间>` 备份；
`data/users.json` 升到 v2（新增字段可选，旧文件可直接读）。

### 5.4 高并发设计

**请求层**：Node 单进程异步 I/O，认证类接口本身不是瓶颈；实测瓶颈在整文件 JSON 写入、
scrypt 计算和 FFmpeg。目标：登录/注册/查询类接口在单机支撑 500–1000 并发请求无异常。

- **存储**：账号、验证码、会话版本、限流计数改 SQLite（Node 22 内置 `node:sqlite`，WAL 模式；
  如不接受实验 API，可换 `better-sqlite3`，接口保持一致）。SQLite 操作是微秒级，单进程可接受；
  按用户拆分的设置/任务索引仍可保留文件，减少写入放大。
- **会话**：改为 HMAC 签名的无状态 Cookie（`userId.expires.signature`，密钥 `data/session-secret` 0600），
  校验时检查 `sessionVersion`；部署重启/未来多进程都不掉线。禁用、改密即递增版本使旧会话失效。
- **验证码**：异步发送队列（进程内 worker，2–4 并发 SMTP 连接，失败退避重试 3 次）；
  发信失败只记日志不影响注册响应；发送前先做数据库限流（邮箱/IP 双维度）。
- **登录防爆破**：限流计数从内存迁到 SQLite（重启不丢），按 账号+IP 双维度；
  `UV_THREADPOOL_SIZE` 调到 8–16 以提升 scrypt 并发（12 核足够）。
- **任务调度**：`maxConcurrentJobs`（默认 2，可配 1–4），全局上限 + 每用户 FIFO 轮询，防单个用户占满；
  每用户排队上限（默认 2）和每日任务上限（默认 20）先做成配置项。FFmpeg 是 CPU 密集型，按核数限制；
  模型调用是外部等待，可在额度内并发。需要横向扩展时，把任务执行拆成独立 worker 进程，共享同一 SQLite 队列。
- **限流与背压**：认证接口按 IP/账号返回 429；请求体仍限 1 MB；上传走流式；
  静态与视频文件继续由 nginx 反代，视频支持 Range。
- **不做**：本阶段不引入 Redis/PostgreSQL/消息队列——单机 SQLite + 进程内队列足够，避免为未验证的规模付复杂度。

### 5.5 安全

- **公开注册必须 HTTPS**：先落域名 + 有效证书；Cookie 加 `Secure`；nginx 加 HSTS；
  没有 HTTPS 前 `registration.enabled=false`，注册与验证码接口即使被调用也拒绝。
- CSRF：保留 Origin 校验，认证类写接口加双提交 Token（公开暴露后必要）。
- 验证码/密码不写日志；错误信息统一；邮箱只用于认证与必要的账号通知。
- 开放注册后按邮箱/IP 限流，可选验证码（人机校验）与邮箱域名白名单；监控发信失败率与退信。
- 账号删除时清理个人目录与发布记录（P2）。
- 现有抖音/H5 公开回调用签名校验，新增用户维度绑定，避免跨账号伪造。

## 6. 分阶段与工作量

| 阶段 | 内容 | 预估 |
| --- | --- | --- |
| P1 | 邮件通道（SMTP + 可选 API 驱动、平台设置、测试发信）、验证码注册/验证/登录/忘记密码、每用户设置与 API Key（含前端与测试） | 约 1000–1300 行（含测试），需你的发件凭据做最终验证 |
| P2 | 任务/成片/素材/角色/发布隔离 + 归属校验 + 管理员总览 + 数据迁移 + 账号删除清理 | 约 700–900 行 |
| P3 | SQLite 存储、无状态会话、任务有界并发与公平队列、用量/存储配额、HTTPS 与反滥用强化 | 约 600–900 行 |

P1 可先用本地假 SMTP 完成自动化测试；真实送达和部署验证要等凭据。P1 合并后即具备「外部邮箱注册 +
每人自己的 Key」，但内容隔离在 P2 完成前仍按管理员单工作区展示——所以建议 P1/P2 连续实施。

## 7. 待确认的决策

1. **隔离粒度**：是否按推荐的 L1（每用户独立设置/Key、任务、成片、素材、角色、发布）实施？
2. **邮件通道**：用哪种（阿里云邮件推送 / Resend / QQ 或 163 邮箱 SMTP / 其它）？
   请提供发件地址与授权码/API Key；如有可发信域名请一并给出（域名需配 SPF/DKIM）。
3. **注册策略**：开放注册还是邀请码/邮箱域名白名单？是否需要「忘记密码」首期就做（建议做）。
4. **公开入口**：控制台是否有正式域名与 HTTPS 证书？没有的话，注册开关先保持关闭，等证书就绪再开。
5. **配额默认值**：每用户并发/每日任务、存储上限，是否接受第 5.4 节的建议默认（可后调）。

另外确认一个理解：这里的「每个用户配置自己的 API-KEY」指**用户自己的模型厂商 Key**
（脚本/画面/角色图/配音等），而不是平台签发给用户的访问令牌；如果你要的是后者（给外部程序调用平台
API 用的 Key），请说明，这会改变鉴权层设计但可以叠加在 L1 之上。
